# CLAUDE.md — glpi-mcp

**Company context comes first: read [../mojood-master/CLAUDE.md](../mojood-master/CLAUDE.md) and
[../mojood-master/STATUS.md](../mojood-master/STATUS.md), then this file.** Never add a `Co-Authored-By` line (or
any Claude attribution) to a commit message or a pull request description.

**What's here:** a Mojood Connect demo, built for one company (Teclib') to show them their product working
inside Claude. Six tools over GLPI's REST API; the two that change tickets need a confirmation code (`tools.py`);
follow-ups are private to technicians by default. A local GLPI in Docker (`docker/compose.yml` follows GLPI's docker-compose.example.yml, pinned, in UTC;
`scripts/up.sh`, `scripts/reset.sh`) holds the SAMPLE IT helpdesk
of the made-up Harbor Trading (`seed.py`, timeline times set by `docker/backdate.sql`). Private until Hammad sends it; public
(Apache-2.0) after. Same recipe as `../snipeit-mcp`.

## Commands
```
scripts/reset.sh                         # fresh local GLPI + SAMPLE helpdesk (Docker via Colima: `colima start`)
uv run --env-file .env glpi-mcp          # http://127.0.0.1:8006/mcp ; add --stdio for Claude Desktop
uv run --env-file .env pytest            # unit tests + live tests against the local GLPI
uvx ruff check --line-length 120 src tests
```

## Rules
- Secrets (`.env`, `docker/.env`: the API user's and database passwords) are generated by `up.sh`,
  git-ignored, and never printed, copied into docs or chat.
- Everything in the data is SAMPLE and made up; no real company's data goes in.
- A change tool never acts without its confirmation code; keep the tests in `tests/test_tools.py` passing.
- The demo signs in with the API user's login and password (GLPI 12 keeps API tokens encrypted with its own key).
- GLPI stamps timeline items when they are written: `seed.py` writes `docker/backdate.sql` and `reset.sh` applies it.
